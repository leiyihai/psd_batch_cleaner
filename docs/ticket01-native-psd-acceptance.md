## Photoshop 验收与测试

现有默认入口只选择最深分支，而且要求共享实例对；联盟没有根级共享对，最深分支也不保证终点是 PSD。因此为 `prototype.host_edit_acceptance` 新增两个显式选项：

- `--embedded-format psd`：沿真实原生内容查找，以 PSD v1 结尾的链作为编辑目标；默认仍为此前的最深分支协议。
- `--skip-shared`：显式跳过共享检查，报告 `shared_check: skipped-explicitly`，共享布尔证据为 `null`，不伪造通过；默认仍要求并实际验收共享实例对。此前三份真实样本的共享证据保持有效。

新增 opt-in 测试 `tests/test_native_psd_acceptance.py`，在同一真实外部边界验证：

1. 无编辑嵌入保存对照和实际编辑使用不同隔离副本。
2. 实际打开 ID 1623 的嵌入 PSD，新增唯一隐藏普通图层，保存回主文档，再保存主文档并重新打开，标记仍存在。
3. 独立解析隔离输入及保存文件，目标嵌入头保存前后均为 PSD v1；输入无标记，输出存在且隐藏；根原有图层 ID、名称、可见性保持一致。
4. 编辑结果与无编辑对照、编辑后保存前/重开后、初始渲染/最终渲染，三组根 PNG 解码像素比较均一致。
5. 既有 Python 输出哈希不变，结束文档数为 0。

该测试先因 CLI 缺少参数退出 2，再实现后通过；真实运行约 10 秒，首轮证据在 `native-edit-r1/`，审查后的最终复跑在 `native-edit-r2/`（约 11 秒）同样通过。默认共享协议也通过大厅v2.3.psd 的真实集成回归（`.prototype-data/ticket01-continuation/sample-2/native-option-regression-r1/`，约 27 秒），没有因为支持跳过而削弱默认检查。

另用现有 `prototype.host_acceptance` 完成联盟根及最深 2 层嵌入的保存重开验收，图层快照、根 PNG 像素一致，链上祖先字段不存在，输出未改变，结束文档数为 0。前后快照摘要均为 `72db2f0efcfbcb62f00a26637ec692908c82952715cf0a0572bf1c003cb6656a`，证据在 `host-roundtrip-r1/`。这项最深链检查与单独锁定 PSD 的编辑检查互补，不将二者混为一条链。

## 大厅局部渲染差异的进一步定位

基于 [此前失败及无编辑对照](ticket01-edit-acceptance.md)，本轮对同一大厅 Python 输出制作两个新副本，不新增标记图层，只改变保存分支：

| 无编辑保存操作 | 与初始根 PNG 一致 | 根差异区域 |
| --- | --- | --- |
| 仅打开并保存链首嵌入（ID 475），再保存重开根文档 | 是 | 无 |
| 仅从共享实例 2724 打开内容并保存，从 2590 检查，再保存重开根文档 | 否 | `(1191, 422, 1234, 456)` |

这是分支对照，不代表已逐个排除所有深层分支。第二项单独即可复现此前的相同根差异范围。

进一步只读解析共享保存前后的文件：

- 两个实例共享 `飞行.psb`，内含 239×167、RGBA、8 bit 的单一像素图层（ID 784）。
- 嵌入内容的解压合成像素哈希及唯一像素图层的解码像素哈希均保持一致。
- 两个实例的图层 ID、边界、变换坐标、opacity、blend mode、局部可见性均一致；但两个实例在根文件中保存的解码像素哈希发生变化。
- 根 PNG 差异区域恰与实例 **2590** 的边界 `(1191, 422, 1234, 456)` 一致；另一个实例 2724 的像素也有变化，但不在最终根 PNG 的可见差异区域。

用户提出“操作使图层超出画板显示范围”的假设后，再比较保存前后实际画板描述符：所属“大厅”画板 ID 2797，`artboardRect` 始终为 `(0,0)–(1280,720)`；两个实例的内容边界和变换四角均位于画板内且未变化。内部 `飞行.psb` 画布始终为 `239×167`，其像素图层边界始终为 `(49,27)–(208,153)`，也未越界。证据为 `shared-only/artboard-bounds-inspection.json` 及 `embedded-inspection.json`。当前证据不支持这两个实例或其内部像素图层因操作越出画板/画布的解释；不把普通父组的内容包围盒误当成画板裁切边界。

因此，差异已定位为**对未编辑的“飞行.psb”执行 Photoshop 保存时，共享实例的派生渲染数据被刷新**，而非嵌入源像素被测试图层改写。尚未确定 Photoshop 内部具体重采样/颜色处理算法，也未用原始大文件作同流程宿主基线；不据此宣称任意原稿必然同样变化、差异必然可忽略或全过程像素无损。

证据目录：`.prototype-data/ticket01-continuation/sample-1/save-branch-diagnosis-r1/`，包含 `probe-results.json`，两份独立计划/实际脚本/保存结果/PNG，以及 `shared-only/embedded-inspection.json` 和提取的嵌入内容。每次结束文档数为 0，大厅既有 Python 输出指纹保持不变。
