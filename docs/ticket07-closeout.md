# Ticket 07：逐文件结果、真实统计与 JSON 导出验收

## 已确认范围与接口

用户确认三个接缝：共享批处理记录、共享统计/导出接口、真实 GUI 操作；并确认 UTF-8 JSON、独占创建、拒绝覆盖的导出选型。本轮仅实施 07，不标记 08 最终整体验收或并行发布完成。

新增 `prototype/results.py`，由同一实现解释批处理记录、计算汇总、生成详情与 JSON 导出。GUI 不另算收益、不通过重新解析输出文件获得统计；耗时导出在非 daemon 后台线程，Tk 只展示消息与结果快照。

## 数据和统计语义

- 批处理行新增 `published`：仅本轮独占发布副本成功后置为 true；历史复用和未发布为 false。自动 `report.json` 仍为逐文件列表，保留现有字段并新增归属和已知大小信息。
- 大小未知用 null/缺失表达，不填零。可读源在哈希后记录原始大小；成功发布记录实际结果大小；缓存命中记录本次核实的历史输出大小。历史条目没有文档/外链数量等元数据时显示未知，不编造为零。
- 五种状态分别计数。成功或删除字段数量不替代完整/部分清理语义；详情说明文档数量为已检查文档数（含无需清理），删除祖先字段数不证明完整成功。
- 本轮收益 = 对 `published=true`、状态为成功/无需清理/部分清理、有输出引用且两个大小均为非负整数的行，累计 `before - after`。bool、字符串、缺失或负的大小无效，不伪造收益。
- 部分清理计入可核实的实际字节差异，同时单列计入数量与差异，并明确不等于完整成功。负值保留，表示体积增加；原样副本可以计入文件数但收益为零。
- 历史复用、失败、未发布和未知大小不计入收益。已发布但缓存等后续失败的文件保留实际路径和已知大小，仍不计入收益。旧记录没有发布归属时不推测为本轮发布。
- 数值为批处理时已核实的记录快照，不承诺持续监控后来被外部修改/删除的文件。

GUI 保留简洁结果表，选择一项后在可滚动详情中查看完整长路径、前后大小（精确字节和 B/KiB 等单位）、真实差异、数量、逐条未处理内容与完整错误。任务终态显示五类数量和收益口径；运行中明确提示终态再汇总，不展示过期收益。文本按实际窗口宽度换行，默认高度适应屏幕；可见冒烟发现底部裁切后已压缩详情/日志初始高度并补窄窗口回归。

## 导出语义与安全

JSON 包含 `format_version`、`task`、`summary`、`benefit_policy`、`results`。`results` 原样保留 GUI 收到的同一批处理记录；`summary` 与 GUI 调用同一个 `summarize()`；未知字段值保留 null，不从字符串化展示反推数值。

`task` 保留提交参数快照、`state`、`completed`、`total`、`source_report` 和错误 `message`。`finished` 只表示本轮已处理结束，仍须核对文件失败/部分清理；`error`、`stopped` 不等同全量完成。扫描或准备失败时总量未知为 null，不能伪造为零总量。

- JSON 非表格，不求值 `=中文...` 等用户可控文本，不引入 CSV/表格公式注入语义；支持完整中文、换行、错误和未处理明细。
- 先序列化验证 JSON，再独占 `open('x')` 创建文件，任何已有目标（包括来源文件）均拒绝覆盖。正常 I/O 异常关闭并清理本次新建的未完成导出，不删除被拒绝的既有目标；不承诺断电/进程强杀时导出原子发布。
- 只在批处理终态允许导出；导出期间锁定目录/开始/导出，禁止重复任务与中途销毁窗口，仍可重绘和查看结果。任务与行在导出开始时冻结；后续程序性修改目录变量不改变导出所属任务。
- 对话框取消、目标冲突、I/O 错误、线程启动失败均不改批处理状态或已保存报告，反馈在导出状态与活动记录，可安全重试。成功不逐文件弹窗。
- 若自动报告更新失败，导出仍保留此前已接收的实际行，可能多于最近可靠 `report.json`；任务异常消息、处理数/总量明确解释这个差异，绝不冒充全量成功清单。

## 红→绿与回归

1. 共享批处理测试先因缺少发布归属失败，再补 `published` 和已知大小；验证真实成功/无需清理/部分清理/损坏文件及下一轮历史引用。
2. 固定结果场景先因没有共享模块失败，再补统一统计；7 行固定场景覆盖全部状态、减少/不变/增加、未知大小、已发布但失败及未发布，独立字面期望为净减少 **984 字节**，其中部分清理 **-40 字节**、1 个已发布大小未知未计。
3. 详情/分类文案测试先因缺少展示接口失败，再补精确字节、易读单位、负数、未知、数量及逐项未处理内容。
4. JSON 导出测试先因缺少接口失败，再补中文与完整字段及拒绝覆盖；fsync 故障测试先复现遗留半成品，再补关闭清理及重试。
5. 真实 Tk 详情/分类和导出按钮测试分别先失败，再接入同一结果模块；窄窗口测试先因未随窗口宽度换行失败，再补动态换行。
6. 文件系统边界注入验证导出磁盘错误、已有用户文件、冻结快照与主线程响应；操作系统线程/文件对话框异常单独验证恢复。没有 mock 清理算法、模拟内部清理调用次数或新造一套 GUI 业务实现。

主要文件：`tests/test_results.py`、固定数据 `tests/result_scenarios.py`、`tests/test_gui.py`。固定场景只表示稳定结果记录，不伪称真实 PSD 原生兼容性；真实 GUI 另通过 `batch.run()` 和真实文件完成端到端。
