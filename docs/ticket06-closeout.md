# Ticket 06：GUI 增量清理验收

## 范围与实现

沿用唯一共享入口 `batch.run()`，没有 GUI 专用缓存或清理实现。仅实施 06，不交付 07 的完整统计与报告导出，也不提前交付 08。

- 缓存继续以解析后的源绝对路径作为身份键，绑定源 SHA-256、清理规则版本、成功/无需清理状态、相对输出路径、输出 SHA-256；兼容已有合法记录，不改变清理规则身份或算法。
- 新增记录预检：JSON、顶层/条目类型、源身份、必要字符串字段、两个 64 位十六进制 SHA-256、可复用状态及输出引用必须有效。损坏记录不静默当作缓存未命中，不覆盖原缓存；发出任务错误并释放自有锁，原稿、已保存报告和输出保留。
- 输出引用必须是指定输出内的相对路径；拒绝绝对路径、盘符相对路径、父级跳转和解析后越界。缓存加载与使用历史副本前均核验解析后的路径，含 Windows junction；越界不读取历史副本字节。使用阶段发现记录失效同样终止任务，不冒充正常全量完成。
- 合法缓存仅在输入、规则及输出哈希均匹配、复用前再次复核源内容后命中；二次运行返回实际历史路径，不在本轮目录复制、解析、清理或保存另一套副本。历史缺失、篡改、源内容变化或规则变化仍按原有机制生成独立新副本。
- 失败/部分清理不写成完整可复用记录，后续继续重试。输入在哈希、历史校验及清理期间变化时明确失败，不发布过期副本。原有完整读盘成本、保真门禁和“不提供持续写入事务快照”的边界不变。
- GUI 初始状态与启动日志明确“完整读盘”及 SHA-256 成本；终态说明历史复用数量、“不在本轮重复复制”和逐文件实际路径口径。输出列注明含历史副本；选择未变化项显示复用说明与完整历史路径，不让用户误以为本轮目录是一套全新完整副本。

缓存异常的人工恢复说明在 README：先确认无任务、备份检查记录；确需重建可将缓存改名留存后重新运行，不需要删除原稿或历史输出，无静默重置/强制解锁。

## 已确认测试接缝及红→绿

用户确认两个接缝：共享批处理入口（复用、失效、并发变化与异常引用），真实 GUI → 实际文件结果（完整复用说明、路径定位、失效后生成）。

1. 公共 `run()` 损坏条目测试先因未抛任务异常失败，补充记录结构拒绝。
2. 越界/绝对/盘符相对路径测试先因静默重新清理并发送完成失败，补充输出路径边界及使用前复检。
3. 非法/缺失规则、哈希、状态与源身份测试先因静默缓存未命中失败，再补完整必要字段校验。
4. 真实 GUI 连续两轮测试先因没有完整读盘和历史复用提示失败，再补界面说明、计数和详情。
5. 在既有保护上增加真实回归：成功/无需清理两种命中；同大小同 mtime 的源修改；规则升级；历史缺失/篡改；部分清理和失败重试/修复；三个输入变化时点；异常缓存拒绝及人工恢复后复用。

测试不模拟清理私有调用次数。输入变化在 `Path.open`/实际流读取的文件系统边界注入，同大小并恢复 mtime，使用真实哈希、校验、清理与落盘报告；规则变化仅替换规则身份常量。缓存命中检查无清理/校验阶段、无新瘦身文件、实际路径及哈希一致，另在文件系统边界拒绝新清理输出写入。

`tests/test_incremental.py` 验证公开批处理、记录绑定、字段/路径拒绝、无重复副本和真实 junction。junction 测试分别覆盖加载时已越界、加载后在“检查变化”阶段被切换到外部位置，明确拒绝读取外部数据。

`tests/test_gui.py` 验证完整 GUI 参数到共享批处理的上述场景，检查状态、活动日志、完整详情、输出字节、缓存、报告及恢复状态，而非只检查静态页面或按钮文字。既有 `tests/test_prototype.py` 哈希与输入变化回归原样保留。

## 测试生命周期诊断

首轮全套回归暴露多窗口 Tk 测试夹具的 GC 问题：已销毁窗口的循环引用被后续后台线程 GC 回收，导致 `Variable.__del__` 报 `main thread is not in main loop`，并可能触发 Tcl 跨线程析构崩溃。

通过两窗口隔离脚本 `.prototype-data/ticket06/diagnose_tk_gc.py` 在第二个任务读盘时强制 GC，稳定复现；线程栈显示停在 Tk 变量析构而非哈希/文件写入。仅在测试夹具 `setUp` 的主线程先回收上一用例的不可达 Tk 引用，同一复现转绿；未放宽超时，未修改生产 GC 策略。新增后台 GC 真实 GUI 回归，检查任务、输出和报告完成且无不可抛出的析构异常。完整回归随后通过，无该错误。
