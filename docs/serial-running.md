# 串行桌面与外部定期运行指南

## 安装与环境

本轮验证环境为 Windows 11、Python 3.14.4、psd-tools 1.26.1、Tcl/Tk 8.6；不把其它平台或 Python 版本算作已验收。使用带 Tcl/Tk 的 Python 安装，不需要安装或启动 Photoshop 来正常清理。

```powershell
cd E:\psd_batch_cleaner  # 换成实际仓库目录
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m prototype.gui
```

当前交付是从仓库启动的串行 Python 桌面工作流，不包含 exe 安装包、自动更新、内置计划任务、实时监听或并行模式。开发测试与显式宿主验收另装 `requirements-dev.txt`，不是正常清理的 Photoshop 依赖。

## GUI 使用

1. 先备份素材，用少量副本验证。选择输入目录及独立输出目录；两者不能相互包含。输出盘必须支持同卷硬链接发布（本轮使用 NTFS），并有足够空间保存新结果及临时文件。
2. 默认“包含子文件夹”，可关闭；PSD/PSB 扩展名不区分大小写，不进入符号链接/目录联接。输出保留相对路径，同名文件不会因子目录不同而互相覆盖。
3. 开始后耗时工作在后台；阶段、文件进度、五类状态与完整详情均可查看。“安全停止”只请求在当前文件完成或安全失败后不再启动下一项；请求中不等于已停止。扫描中的请求等待扫描安全返回，不强行中断文件系统调用。
4. 结束后选择文件查看实际输出路径、大小、未处理内容及错误。部分清理并非完整成功；无需清理仍生成原样副本，未变化引用已核实的历史副本。本轮目录可能只有报告及部分新文件，不是一套重复复制的完整结果。
5. “导出 JSON…”要求一个尚不存在的目标。中文 UTF-8 JSON 包含同一批记录、统计口径及完成/停止/异常上下文；导出期间不能启动另一任务或关闭窗口中断写入，失败可重试。已有目标一律拒绝覆盖。

本轮收益只计本轮实际发布、非失败且大小已核实的结果；部分清理的实际差异计入但单列，历史复用不重复计入。未知大小不补零，净减少为负表示体积增加。结果快照不是之后对外部改动的实时监控。

## 非交互入口与退出码

在仓库目录执行，与 GUI 复用同一个 `batch.run()`、深度清理、缓存、发布和自动报告实现：

```powershell
.\.venv\Scripts\python.exe -m prototype.batch --input "D:\输入" --output "E:\独立输出"
.\.venv\Scripts\python.exe -m prototype.batch --input "D:\输入" --output "E:\独立输出" --no-recursive
.\.venv\Scripts\python.exe -m prototype.batch --help
```

| 退出码 | 含义 | 外部任务处理建议 |
| ---: | --- | --- |
| 0 | 本轮无单文件失败、无部分清理；结果可以是成功/无需清理/未变化，或明确的空范围 | 读取终态和报告核对总量，不必重复复制历史结果 |
| 1 | 至少一个单文件失败；其它文件仍处理，可能同时存在部分清理 | 检查逐项错误与已有输出，不当作全量成功 |
| 2 | 任务无法继续（目录/锁/缓存/报告/基础设施异常）；命令行参数错误也使用 argparse 的 2 | 检查 stderr 和可靠报告，解决原因后再运行；不要强制解锁 |
| 3 | 无单文件失败，但至少一个部分清理 | 复查未处理内容，不当作完整成功；这些文件下次仍重试 |

优先级：任务异常 **2** > 单文件失败 **1** > 部分清理 **3** > 正常 **0**。这改变了旧 CLI 对“仅部分清理”返回 0 的行为；已有外部脚本必须相应更新。数字不是按大小表示严重性。

程序正常完成其终态处理时，stdout 最后一行是可解析的 JSON，例如：

```json
{"state":"finished","exit_code":3,"completed":2,"total":2,"counts":{"成功":0,"无需清理":1,"未变化":0,"部分清理":1,"失败":0},"report":"E:\\独立输出\\本轮目录\\report.json","message":""}
```

任务异常使用 `state: "error"`、`exit_code: 2`、明确 message；总量尚未扫描可靠时为 null，未产生可靠报告时 report 为 null。`completed` 和 counts 表示已实际接收到的逐文件结果；若报告更新失败，原报告可能少于这个数，不能假定它包含完整清单。`finished` 表示处理范围已结束，不表示所有文件完整成功，仍须检查退出码及文件状态。

阶段日志和报告路径提示仍位于该终态行之前。CLI stdout/stderr 使用 **UTF-8**（包括帮助信息），Python 调用方应指定 `encoding='utf-8'`，不要依赖 Windows 默认 GBK 解码。终态 JSON 本身为 ASCII 转义 JSON，仍可无损解析中文。

参数语法错误可能只输出 argparse usage/error 而没有终态 JSON。外部强杀、断电、外围超时或其它没有完整终态的运行也不能视为通过；计划任务必须同时识别异常退出/超时，不把不完整 `report.json` 或缺失终态推断为成功。强杀不等同 GUI 的安全停止；本轮不承诺其会运行清理 finally 或留下完整报告。

## 交给外部计划任务

可以使用 Windows 任务计划程序或现有调度器，本工具不自动注册任何任务。

- **程序**：实际仓库中的 `.venv\Scripts\python.exe` 绝对路径。
- **参数**：`-m prototype.batch --input "D:\输入" --output "E:\独立输出"`，按需要追加 `--no-recursive`。
- **起始目录**：仓库绝对路径，确保可以找到 `prototype` 模块；不要依赖交互终端的当前目录或 PATH。
- 运行账户须能读输入、写输出并创建硬链接；计划任务账户看不到的映射盘应改用该账户有权访问的实际路径。普通 CLI 无需桌面、Photoshop 或逐文件确认。
- 采用不重叠运行策略，保留任务结果码和原始日志。即使调度器误重叠，同一输出目录仍由独占锁拒绝第二任务。
- 依据真实耗时、输入规模和设备余量设置超时。本轮完整真实 CLI 批次约 319–322 秒，不要用短于实际任务时长的外围时限。没有完成终态或非 0 结果必须显式复查，不无限自动重试。

如需用 Python 外层脚本原样保存 UTF-8 日志并向调度器透传退出码，可采用下列形式（只做进程调用，不构成内置定时器）：

```python
from pathlib import Path
import subprocess

repo = Path(r"E:\psd_batch_cleaner")
logs = repo / "run-logs"
logs.mkdir(exist_ok=True)
with (logs / "stdout.log").open("ab") as out, (logs / "stderr.log").open("ab") as err:
    result = subprocess.run(
        [str(repo / ".venv/Scripts/python.exe"), "-m", "prototype.batch",
         "--input", r"D:\输入", "--output", r"E:\独立输出"],
        cwd=repo, stdout=out, stderr=err, shell=False,
    )
raise SystemExit(result.returncode)
```

自行安排日志轮换和磁盘空间，不将固定日志名视为每次运行的完整历史；每轮自动报告仍在独立输出目录中。不要仅把 CLI 加到 shell 管道后查看最后一个非 Python 命令的状态码，从而丢失清理进程的真实退出码。

## 增量、失败复查和遗留锁

- 源身份、源 SHA-256、规则、可复用状态、实际输出路径及输出 SHA-256 全部有效才复用。仍会完整读盘；大小和 mtime 一样不能代替内容哈希。
- 成功/无需清理可复用，失败/部分清理不缓存成完整结果；源、规则或历史输出变化重新发布新路径，不覆盖既有副本。输入持续修改时不提供事务快照，请先停止其它写入者再重试。
- 损坏缓存或越界引用明确终止；先确认无任务，备份检查 `.cleaner-cache.json`，确需重建可改名留存后重跑。不要为了“跳过”而把部分清理手改成成功。
- `.cleaner.lock` 冲突不能自动强制移除。检查 GUI、调度器及使用该输出目录的进程，确认确无任务后，再备份/人工处理遗留锁。PID 可能复用、权限或会话可能不同，不能只凭一个 PID 就断定可删锁。
- 任务异常保留既有副本和最后可靠报告；未记录到报告的已发布副本可能出现在 GUI JSON 导出中，须连同 task 错误和总量看待。未完成暂存文件不是成功副本，不因它存在就忽略失败。

## 支持边界与宿主验收

正常路径不合并/栅格化图层、不重新编码像素、不跟随外链；无法验证的格式或结构拒绝发布。XMP、替换数据、图层记录、合成图、深度等限制见 [ADR](adr/0001-stream-metadata-patches.md)，不是无限大小或任意文件无损保证。四份真实大文件仍为部分清理；Python 不为了接近 JSX 体积而删除未知内容。

Photoshop 仅用于显式验收，不是计划任务依赖。使用开发依赖及已运行、空闲、无任何已有文档的会话；只在新隔离副本上验证，原稿及既有清理稿不作为保存目标。前置检查不满足、宿主失败或超时就停止，不自动重试、点击任意弹窗或结束 Photoshop。watchdog 退出不保证取消已提交的宿主操作，须人工检查会话后才能决定下一步。

本轮四份宿主检查、资源测量、未完成尝试和限制见 [08 整体验收](ticket08-closeout.md)，此前未知数据“保留图层”白名单和实机证据见 [02 最终记录](ticket02-closeout.md)。这里的通过仅限代表性材料和已执行操作，不保证全部嵌入分支、全部滤镜或持续无人值守运行绝对安全。
