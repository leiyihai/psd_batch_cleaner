# psd-tools 深度清理验证原型

> 本文保留早期内存型原型及四个官方小样本的历史验证记录。工单 01 已新增文件区间批处理并验证用户提供的三份大文件；当前策略、资源限制、真实结果及未完成的 Photoshop 深层验收以 [真实文件验收记录](real-file-acceptance.md) 和 [大文件策略 ADR](adr/0001-stream-metadata-patches.md) 为准。下文的 2 GiB 全量限制和 16 项测试是早期状态，不代表新的批处理入口仍使用该方案。

## 阶段与已确认范围

这是完整 GUI 开发之前的可行性验证原型，不是已完成的桌面应用。

- 正常清理过程不启动 Photoshop，固定使用 `psd-tools==1.26.1`。
- 与原 JSX 的清理目标一致：只删除 Photoshop XMP 命名空间下的 `DocumentAncestors`，不删除作者、版权、其他元数据，不合并或栅格化图层。
- 递归处理 DATA 类型中实际以 PSD/PSB 文件头开头的嵌入内容，不跟随 EXTERNAL 外链。
- 非 PSD/PSB 嵌入内容、别名或超过深度限制的内容原样保留，并报告“部分清理”。结构解析、XMP 解析或写回验证失败时，不发布该文件的结果。
- 原文件不覆盖；没有需要删除的数据时原样复制。
- 输入与输出目录不得相互包含。每次运行在输出目录生成独立时间戳子目录，保留输入相对路径；输入变化时不会覆盖上次结果。
- 当前串行处理，预留文件边界停止接口。功能验收后再根据真实文件的峰值内存和磁盘吞吐确定并行数，不直接按 CPU 核数并行。

## 为什么固定版本、增加严格门禁

本机原有的 psd-tools 1.17.0 不完整支持 linked-layer version 8 的 content descriptor；使用项目虚拟环境，不修改全局安装。

实现使用低层 `PSD.read/write` 和 linked-layer 数据结构，而非声称高层 API 原生支持智能对象编辑。写回嵌入 DATA 的 data 字节，由库重新计算长度，保留 UUID，不自行更改外链 filesize 或共享标识。

修改某个文档前，要求它在**不修改时能够逐字节读写往返**；无法往返的文件拒绝发布，而不是静默丢弃未知数据。末尾分配填充单独保留。修改后重新解析、验证结构与合成图存储数据。未改动的文档保持原始字节。

XMP 使用命名空间识别、字节区间删除，不重新格式化整份 XML；支持属性与元素两种 RDF 表达，保留其他字段和 packet padding。暂不支持含 NUL 的编码及 DTD。

这些检查是安全门禁，**不是任意 Photoshop 文档兼容性或绝对无损保证**。

## 增量规则

输出目录的 `.cleaner-cache.json` 保存：源绝对路径、源 SHA-256、规则版本、输出位置、输出 SHA-256、处理状态。

- 只有“成功”“无需清理”可命中增量缓存。
- 源内容改变、规则变化、输出丢失或内容改变均需重新处理。
- 文件大小、修改时间不作为内容相同的最终依据。
- 哈希检查有单独阶段提示；缓存命中前复核源内容，避免核对旧输出期间输入被修改。
- 失败和部分清理均不缓存为完整结果，下次会重试。
- 输入在处理期间发生变化则不发布结果；使用者仍应避免同时编辑正在处理的源文件。
- 同一输出目录有运行锁；异常退出后遗留 `.cleaner.lock` 时，应确认无任务运行后手动移除。

输出先写临时文件、同步并核对哈希，再用不覆盖既有路径的硬链接发布。当前原型要求输出文件系统支持硬链接（如 NTFS）；不支持时明确报错，不降级成覆盖写入。

合成容器样本用于验证底层结构，不等同于 Photoshop 原生智能对象的验收证据。

### 四个官方真实样本

来源固定为 [psd-tools v1.26.1 测试文件](https://github.com/psd-tools/psd-tools/tree/v1.26.1/tests/psd_files)，下载不提交到仓库。

| 样本 | 含明确测试祖先字段的副本结果 | 检查 |
|---|---|---|
| smart-object-slice.psd | 主文档与内部 PSB 各清理 1 项 | 合成图、图层存储不变 |
| smart-object-slice.psb | 主文档与内部 PSB 各清理 1 项 | 合成图、图层存储不变 |
| smart-object-v8.psd | 主文档清理 1 项，嵌入 PNG 原样保留 | 部分清理，version 8 信息保留 |
| placedLayer.psd | 主文档清理 1 项，跳过 2 个外链，嵌入 PNG 原样保留 | 部分清理，外链条目原样保留 |

样本同时对原版执行清理，并对**明确注入测试 XMP 的独立副本**验证删除路径。不能将注入后副本的往返成功说成原版全部内容的无损证明。具体原版状态、下载地址和 SHA-256 在 `.prototype-data/sample-report.json`。

执行两轮 CLI 后，两个完整成功的智能对象样本命中“未变化”，两个部分清理样本按规则重新尝试。

- 对应图层名称、类型、可见性、不透明度、混合模式和边界一致。
- 四组 Photoshop 实际渲染的 PNG，解码为 RGBA 后逐像素相同。
- 该次检查前后文档数量均为 5；测试打开的文档不保存关闭，恢复原活动文档与对话框设置。

报告：`.prototype-data/photoshop-report.json`，渲染图片位于 `.prototype-data/renders/`。报告已经对属性、图层快照、像素比较增加自动断言。

## 复现方式

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m prototype.verify_samples
.\.venv\Scripts\python.exe -m prototype.batch --input "D:\测试输入" --output "D:\测试输出"
```

可选的 Photoshop 验证只用于验收，不属于正式清理依赖。需要单独具备 `pywin32`、`Pillow` 的 Python，以及已经打开的 Photoshop：

```powershell
python -m prototype.photoshop_verify
```

它仅访问 `.prototype-data/injected` 和 `cleaned` 的四个固定测试文件，不自动启动、退出 Photoshop，也不保存输入 PSD。请在 Photoshop 空闲时执行；不要同时手动操作。渲染副本和报告由验证脚本创建。

## 尚未验收

- 用户报告 Photoshop 的“此文档包含未知数据”警告可能导致原 JSX 流程中断。默认策略应为“保留图层”，不是“拼合”；警告同时说明该选项可能丢弃未知数据，因此不能把自动确认当成无损保证。Python 正常流程不调用 Photoshop，但仍需用相应真实文件验证未知数据的解析与写回；无法安全保留时必须不发布修改结果、记录原因并继续后续文件，不得弹窗等待或自动拼合。本项尚未针对性复现或验收，现有往返门禁不等于该兼容性问题已解决。
- 用户真实大文件、数千图层、超大 PSB 的耗时和峰值内存。
- 本原型将整个文件与嵌入内容载入内存；累计解析字节默认上限 2 GiB、嵌套深度默认 16，这**不是**实际进程内存上限。超大文件可能需要流式改写方案，当前不宜直接大规模投入使用。
- 多层和重复载荷已有合成测试，但还缺真实 Photoshop 多层嵌套及多实例共享智能对象样本的完整编辑/保存/重新打开验收。
- 非 PSD 嵌入内容仍不清理，不能宣传与原 JSX 对所有内容的效果完全一致。
- 不支持任意特殊/损坏 PSD；严格门禁可能拒绝一些 Photoshop 可以打开的合法文件。
- 全量定期任务、最终 GUI、日志导出、并行处理尚未实现。CLI 可由外部计划任务调用，但目前不应作为无人值守生产工具。

结论：**直接处理 PSD/PSB 嵌入内容的路线在当前样本上可行，具备继续开发的依据；尚未完成真实大文件验收。**
