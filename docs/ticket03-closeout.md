# Ticket 03：最小中文串行 GUI 验收

## 交付与范围

提供独立 Tkinter/ttk 窗口，启动：

```powershell
.\.venv\Scripts\python.exe -m prototype.gui
```

需要带 Tcl/Tk 的 Python（Windows 官方安装器可选组件）。本机 Tk 8.6 / Tcl 8.6.15 可用，采用标准库避免给正常清理新增 GUI 第三方依赖；ttk 提供一致的控件样式，Tk 主线程只处理界面和消息。

本轮交付输入/输出目录与浏览、开始、当前阶段/文件、基本结果、完整路径/错误详情及既有 JSON 报告位置。**仅处理当前目录，不扫描子目录；受支持嵌入内容仍进行既有深度清理。** 递归选项、停止按钮、完整增量展示、收益统计/报告导出、打包及整体验收不在本轮，不将 04–08 当作完成。

开始后锁定两个目录、浏览和开始按钮；任务参数在启动时冻结。长路径可在输入框横向查看，结果有横/纵滚动条，选择行可读取完整路径、部分清理原因及错误，不逐文件弹成功对话框。

## 共享批处理，不复制业务实现

- `prototype.batch.run(..., recursive=False, on_event=...)` 是 GUI 调用的同一批处理入口。`recursive` 默认仍为 True，现有 CLI/验收调用保持默认递归；没有在 GUI 另写扫描器或清理器。
- `BatchEvent` 提供 phase / file / error / finished 事件，包含源路径、逐文件结果和报告位置；原来的 `emit` 文本观察方式继续可用。
- `clean_file` 的可选 `on_validate` 在临时文件落盘、开始区间比较和输出重解析之前发出真实校验阶段。没有在校验结束后补发假进度；未改变补丁内容、保真门禁、规则版本或发布顺序。
- 后台非 daemon 线程执行路径展开、目录校验、扫描、哈希、清理、校验、报告和缓存写入；通过队列回到 Tk。worker 不调用 Tk。每次最多消费100条通知，避免大量小文件消息独占事件循环。
- 使用不定进度条，不声称阶段百分比、预计剩余时间或尚不可靠的文件总量。

共享入口先确认输入存在、解析真实路径并拒绝输入/输出相互包含；输出目录创建及独占创建任务锁是实际写权限检查，早于任何输入清理。不能获得写权限或已有任务锁时明确报任务异常，不覆盖锁。写回仍使用临时结果、区间校验、源哈希复核和不覆盖发布；无需清理仍原字节复制，外链和非 PSD/PSB 保留策略不变。

空输入/输出框不启动任务。目录错误、线程启动错误及 worker 准备错误均恢复控件并展示错误；文件级失败继续后续文件，任务级基础设施失败不显示为正常完成。部分清理与失败保留实际状态，不把所有结束都写成“全部成功”。基础设施错误前已发布的输出及报告仍可定位。

本轮没有停止按钮。运行中关闭窗口会提示等待本轮安全结束，不销毁窗口或强制中断写入；安全停止交互由05实现。
