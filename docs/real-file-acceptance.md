# 工单 01：用户真实文件深度清理验收记录

## 结论与工单状态

已用用户授权的三份瘦身前文件执行新的文件区间批处理，并与 JSX 瘦身后文件只读比对；三份原稿及三份参考文件的前后 SHA-256 均一致。已获得真实瘦身、内存、多层嵌入和共享实例的自动检查证据；**Photoshop 深层编辑及保存重开验收未全部完成，工单 01 尚未验收完成，不能解除 GUI 前置依赖。**

三份结果都含不处理的非 PSD/PSB 嵌入内容，按已确认规则标为“部分清理”。这不是报错或任务中断，也不等于对所有格式完成了深度清理。

## 方法与环境

- Windows 11，Python 3.14.4，psd-tools 1.26.1，串行、每样本独立子进程。
- 样本由用户明确提供：瘦身前为输入，瘦身后为 JSX 参考。原始素材、输出及完整本地日志不提交到 Git。
- 规则版本：`ancestors-file-patches-v3-validated-psdtools-1.26.1`。
- 完整报告：`.prototype-data/user-acceptance-final/20261113_194622_237572/acceptance.json`。
- 新清理路径仅对 XMP、包围内容的长度字段及必要 padding 做补丁；图层记录、共享 ID、非 PSD 嵌入内容和其他未知区间不重序列化，写后逐块比对所有未修改区间及补丁字节，再重新扫描输出确认受支持内容无待删除祖先字段。
- 每个 XMP 最多 128 MiB，累计替换字节最多 256 MiB，嵌套深度最多 16，文档及条目数量有安全限制。LayerInfo、Lr16/Lr32 替代图层记录区和解压合成图分别有 128 MiB 校验上限；RLE 行表最多 8 MiB，单行压缩数据最多 16 MiB；暂不支持验证的 Layr 替代存储明确拒绝发布。大块嵌入 DATA 采用区间定位和 4 MiB 分块复制，不通过扩大旧累计 2 GiB 限制解决大文件问题。
- 修复 XMP 解析器回调闭包的循环引用，使大 packet 在返回时立即释放；已增加禁用循环 GC 的批处理回归。修复前真实峰值可达 2.67 GiB；仅区间复制版本约 142–143 MiB，加入严格图层及合成图校验后的复跑测量如下。
- Windows 虚拟环境解释器可能由 launcher 启动实际子解释器，资源监控覆盖整个自建进程树，超限或超时只结束自建验收进程，不结束 Photoshop 或用户进程。每个 worker 自报 Windows PeakWorkingSetSize，避免仅测到几 MiB 的 launcher。

### 自动检查通过项

性能表对应严格常规 LayerInfo、linked 必需后缀及合成图校验版本的实跑；随后补齐 Lr16/Lr32 和非法单字节通道门禁，已对同一三份输出再次严格扫描，全部通过且无需新补丁，但没有再次重测性能。三份输出大小和指纹未因这些只读门禁而改变。
- 三个原稿及 JSX 参考集均未变化；每个结果保存于独立输出位置。
- Python 结果均保留输入的 1280×720、RGB、8 bit、3 通道头信息。
- Python 与输入的根图层记录数、智能对象实例数及共享 ID 组数相同。
- Python 与输入的解压根合成像素 SHA-256 相同；更强的未修改区间比较覆盖了嵌套内的图层、像素与未知数据字节，不只比较数量。
- 多层嵌入区域写回后可重新扫描，受支持 XMP 中应删除的字段不再产生补丁。

### JSX 参考集的使用限制

三份 JSX 参考的根合成像素均与对应输入不同。其中通行证参考为 **1603×720、4 通道**，输入及 Python 结果为 **1280×720、3 通道**。因此这组文件不是“只删除元数据”的逐像素等价基线，不能要求 Python 为追求更小体积而复刻这些差异。

这些是对现有文件的观察，不足以将差异归因于 JSX 本身；可能包含用户的其他编辑或不同保存状态，尚未确定来源。

## 复现

先安装开发验收依赖，正常清理仅需要运行依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m prototype.acceptance `
  --input "测试psd比对\瘦身前psd" `
  --reference "测试psd比对\瘦身后psd" `
  --output ".prototype-data\user-acceptance" `
  --memory-mib 2048 --timeout 600
```

输出报告记录本次独立输出位置。仅在 Photoshop 无打开文档且空闲、确认前次验证已结束时，才可显式运行宿主验证：

```powershell
.\.venv\Scripts\python.exe -m prototype.host_acceptance `
  --report "<本轮 acceptance.json>" `
  --output "<本轮报告目录下尚不存在的隔离目录>" `
  --timeout 180
```

正常批处理无需 Photoshop：

```powershell
.\.venv\Scripts\python.exe -m prototype.batch --input "D:\输入" --output "D:\独立输出"
```
