# PSD/PSB 深度瘦身桌面批处理工具

## Problem Statement

用户已经通过现有 Photoshop JSX 脚本获得了良好的瘦身效果，但使用成本较高：复杂 PSD/PSB 含成百上千图层或嵌套智能对象时，清理需要长时间占用 Photoshop，期间难以继续正常工作；用户需要手动选择脚本，逐文件处理和重复运行都不方便。

用户希望将工具改为 Python 桌面应用，使用 psd-tools 直接处理文件，通过简易、美观的中文 GUI 输入文件夹路径、批量生成瘦身副本，而不是继续依赖 Photoshop 内的脚本启动流程。用户还需要定期重复运行时跳过没有变化的文件。

“深度清理”不能静默退化成“主文档清理”。现有 JSX 的设计意图是删除当前文档的文档祖先元数据，再打开智能对象递归处理内部文档。新的直接文件处理方案需要验证嵌入式 PSD/PSB 的递归清理与正确写回，并明确不支持内容的边界。

## Solution

提供以 Windows 为首要使用环境的中文单窗口 Python 桌面工具。用户可以填写或浏览选择输入目录、独立输出目录，默认包含子文件夹，批量查找 PSD/PSB。

正常清理过程不启动、不调用 Photoshop。工具使用 psd-tools 清理主文档及受支持的嵌入式智能对象中的文档祖先元数据，只删除 Photoshop XMP 命名空间中的 DocumentAncestors，不修改其他元数据或视觉内容。

工具保留原文件，生成独立瘦身副本并保留输入相对目录结构。不能安全处理的嵌入内容原样保留，明确标记“部分清理”；出现结构性解析或写回错误时不发布该文件的修改结果。

界面显示检查变化、清理和校验阶段，以及文件进度、成功、无需清理、未变化、部分清理、失败等结果。用户可以请求停止，当前文件安全完成后不再启动下一个文件。逐文件报告可以查看和导出。

通过源内容哈希、清理规则版本和输出副本校验实现增量清理。重复运行时复用有效历史输出，不再重复解析、递归清理或保存。先完成串行版本和真实文件验收，再单独评估受内存及磁盘能力约束的并行处理。

## User Stories

1. 作为需要瘦身设计稿的用户，我希望直接启动独立桌面工具，以便不再手动进入 Photoshop 选择 JSX 脚本。
2. 作为用户，我希望正常清理不需要启动 Photoshop，以便不再让 Photoshop 承担批处理执行工作。
3. 作为用户，我希望看到简洁、美观、中文的单窗口界面，以便快速理解操作步骤。
4. 作为用户，我希望可以手动填写输入文件夹路径，以便处理已知位置的设计稿。
5. 作为用户，我希望可以浏览选择输入文件夹，以便减少手动输入路径的错误。
6. 作为用户，我希望选择独立输出文件夹，以便清理结果与原稿分开保存。
7. 作为用户，我希望默认扫描子文件夹，并可以关闭递归扫描，以便选择本轮处理范围。
8. 作为用户，我希望同时识别 PSD 和 PSB，包括大小写不同的扩展名，以便无需手工分类文件。
9. 作为用户，我希望中文、空格和多级目录路径能被正确处理，以便使用现有素材目录。
10. 作为用户，我希望输入目录不存在或输出位置不合法时得到明确提示，以便在开始前修正错误。
11. 作为用户，我希望输入与输出目录不能相互包含，以便避免把历史结果再次递归处理。
12. 作为用户，我希望源文件永远不被清理过程覆盖，以便保留可恢复、可比对的原稿。
13. 作为用户，我希望输出保留相对于输入目录的结构，以便能找到每个结果对应的原稿。
14. 作为用户，我希望不同子目录中的同名文件保持独立，以便避免相互覆盖。
15. 作为用户，我希望重复运行产生新结果时不覆盖既有副本，以便保留历史版本。
16. 作为用户，我希望只删除文档祖先元数据，以便保留作者、版权及其他文档信息。
17. 作为用户，我希望处理主文档内部嵌入的 PSD/PSB，以便获得深度清理而不只是表层清理。
18. 作为用户，我希望递归处理多层嵌入的 PSD/PSB，以便嵌套智能对象中的祖先数据也有机会被清理。
19. 作为用户，我希望共享的智能对象内容及其标识保持一致，以便清理不破坏实例关联。
20. 作为用户，我希望外链源文件不被跟随修改，以便不会意外影响其他引用同一素材的项目。
21. 作为用户，我希望输入范围内的外链源文件可以作为独立目标文件处理，以便不需要因它被其他设计稿引用而排除它。
22. 作为用户，我希望 AI、PDF、PNG 等非 PSD/PSB 嵌入内容保持原样，并得到明确说明，以便知道哪些内容没有完成清理。
23. 作为用户，我希望无法安全清理的文件不被当作成功，以便不会依赖有损或不完整的结果。
24. 作为用户，我希望无需清理的文件原样复制到输出位置，以便首轮结果不会因为没有祖先数据而缺少文件。
25. 作为用户，我希望保留图层结构、像素、智能对象内容关联和可编辑性，以便结果仍可继续用于设计工作。
26. 作为用户，我希望界面在处理大文件时保持响应，以便不会误以为工具已经卡死。
27. 作为用户，我希望看到当前文件及整体进度，以便了解剩余任务。
28. 作为用户，我希望区分“检查变化”“清理中”“校验中”等阶段，以便理解大文件完整读盘的耗时。
29. 作为用户，我希望查看成功、无需清理、未变化、部分清理、失败的数量，以便快速判断本轮结果质量。
30. 作为用户，我希望看到每个文件的原大小、新大小和实际变化，以便判断瘦身收益，而不是只看到删除字段的数量。
31. 作为用户，我希望工具不把体积未减少或增加的情况包装成瘦身收益，以便获得真实统计。
32. 作为用户，我希望可以停止批处理，并在当前文件完成后停止启动下一项，以便安全结束长任务。
33. 作为用户，我希望单个文件失败后继续处理其他文件，以便一个坏文件不阻断全部任务。
34. 作为用户，我希望逐文件查看和导出失败原因及未处理内容，以便有针对性地复查。
35. 作为定期运行清理的用户，我希望内容没有变化的文件直接复用有效输出，以便减少重复解析和保存。
36. 作为用户，我希望即使文件大小和修改时间没有变化，内容改变也会被识别，以便不会错误跳过已更新文件。
37. 作为用户，我希望历史输出丢失或被修改后重新生成结果，以便不会复用无效副本。
38. 作为用户，我希望清理规则升级后重新检查旧结果，以便不会把旧规则下的处理记录当成新规则的完整结果。
39. 作为用户，我希望失败和部分清理文件不会被永久跳过，以便之后修复问题或升级能力后可以重试。
40. 作为用户，我希望源文件在哈希、校验或清理期间被修改时得到提示且不发布过期结果，以便避免处理与当前原稿不对应的内容。
41. 作为用户，我希望可以查看每个增量命中文件实际复用的历史输出位置，以便不误认为本轮目录包含一套全新完整副本。
42. 作为用户，我希望批处理能力不与 GUI 绑定，以便未来可以从外部计划任务调用相同逻辑。
43. 作为用户，我希望同时针对同一输出位置启动任务时得到明确提示，以便避免缓存和结果相互干扰。
44. 作为用户，我希望在正式推广前用真实大文件验收耗时、内存和结果质量，以便不把小样本成功当成所有文件都可靠。
45. 作为用户，我希望后续并行能力采用合理、受控的并行数，以便提高吞吐量时不造成内存耗尽或磁盘过载。
46. 作为用户，我希望遇到 Photoshop 提示包含未知数据的文档时默认保留图层及可编辑性，不因等待人工确认而中断整个批处理，也不通过拼合图层绕过兼容性问题。

## Implementation Decisions

### 架构与交付阶段

- 保留原 JSX 工具；新的正常清理链路独立于 Photoshop 自动化。不以 COM 包或 Photoshop Python 自动化封装替代用户选定的 psd-tools 路线。
- 复用现有原型中的深度清理核心、批处理编排和增量记录能力，不另建一套 GUI 专用清理逻辑。
- 交付顺序为：深度清理原型验证、代表性真实文件验收与必要的核心修正、串行 GUI 和可复用批处理入口。并行处理作为功能验收后的后续阶段。
- GUI 与任务执行隔离，耗时扫描、哈希、解析、清理、写入及校验不占用 GUI 事件循环。具体 GUI 框架尚未选定，不作为已确认技术决策。
- 批处理入口接收目录、递归选项、停止信号及进度接收方，返回逐文件结果与报告信息。现有打印式通知需要扩展为可被 GUI 和非交互入口共同消费的阶段及结果事件。
- 首版默认串行；停止请求在文件边界生效，不在写入一半时强制打断进程。

### 清理边界

- 以命名空间和属性名识别 DocumentAncestors，覆盖 RDF 元素与简写属性表达，不按字符串全局替换，不删除整个 XMP 资源块。
- 保留未涉及的 XMP 字节及字段；不通过整体重新格式化 XML 顺带改写其他元数据。
- 递归处理实际内容为 PSD/PSB 的 DATA 嵌入载荷，不仅依赖文件名扩展名识别。
- 保留智能对象 UUID 及实例关联，不将共享标识、内容标识或外链大小字段随意改写。
- 不跟随 EXTERNAL 外链路径。外链源文件若自身属于输入扫描范围，则按普通独立输入处理。
- 非 PSD/PSB 嵌入内容、别名及受限未处理内容保持原样，逐项报告部分清理，不静默降级为完整成功。
- 任何层级的结构性解析错误、XMP 安全解析失败或结果校验失败，均不得发布该源文件的修改结果。

### 文件安全和结果发布

- 输入目录与输出目录必须独立、不可相互包含；扫描不跟随符号链接递归进入其他目录。
- 保留原文件。无需清理且无未处理内容的文件按原始字节复制，不为了输出而重序列化。
- 沿用原型的独立运行目录策略保存新副本，保留输入相对目录结构；不覆盖旧结果。增量命中时返回历史输出引用，而不是重复复制到本轮目录。
- 采用临时写入、落盘检查、校验通过后发布的顺序，发布不得覆盖已有目标。
- 当前原型使用硬链接完成不覆盖发布；不支持相应能力的输出文件系统应明确失败，不能静默降级成非安全覆盖。
- 保留严格的字节保真门禁。真实大文件采用文件区间补丁时，逐块比较所有未修改区间及预定替换字节，并重新扫描输出；不再要求把整个 PSD 对象重序列化后比较。旧内存型原型仍保留其重序列化门禁。任一路径校验失败均拒绝发布，嵌入内容末尾分配填充原样保留。
- 修改后重新解析并验证结构；像素、图层存储和关联的保留还需要独立测试及 Photoshop 验收，不能只以能重新解析作为无损证明。
- 暂固定 psd-tools 1.26.1，并检查实际运行版本；版本升级必须重新验证，清理规则身份应随兼容性决策更新。

### 未知数据与“保留图层”兼容性

- 用户提供的 Photoshop 警告原文为：“此文档包含未知数据，将扔掉未知数据以保持图层可编辑。若要改为保留原始外观，请选择‘拼合’以将复合数据作为拼合的图像载入。”按钮分别为“保留图层”“取消”“拼合”。
- 用户所述“默认是”在此具体对应“保留图层”，不是选择“拼合”；保留图层和可编辑性优先，不能为了不中断任务而自动拼合或栅格化。
- Photoshop 的“保留图层”选项本身提示会丢弃未知数据，不能将其解释为无损保留全部未知数据，也不能据此授权 Python 丢弃任意未知字段。
- Python 正常清理不调用 Photoshop，因此不通过模拟点击该弹窗解决问题；必须针对引发该警告的主文档及嵌入内容验证解析与写回兼容性，不得假设不用 Photoshop 就没有数据兼容性风险。
- 可以安全保留并通过校验时正常处理；未知数据不能可靠保留或所用路径的字节保真门禁失败时，拒绝发布该文件的修改结果，记录兼容性原因并继续后续文件，不等待逐文件人工确认，不将其标记为成功。
- 如 Photoshop 验收或现有 JSX 的辅助流程遇到该弹窗，期望策略为“保留图层”，并验证实际执行是否遵从该策略；不得仅设置无对话框模式便假定已正确处理。无法自动处理时应明确失败或超时，不能无限阻塞或计为通过。

### 增量清理与结果模型

- 使用源 SHA-256 而不是仅凭大小及修改时间判断输入未变化；接受完整读盘的成本。
- 增量记录绑定源身份、源内容哈希、规则版本、结果状态、输出位置及输出内容哈希。
- 只有成功和无需清理可以复用缓存。部分清理与失败不能记录成完整可复用结果。
- 输出缺失、输出哈希不符、源内容改变或规则变化时重新处理。
- 复用历史输出前再次核对源内容；发布新结果前也复核输入，检测到变化则不发布并报告重试原因。不承诺对正在被其他程序持续写入的文件提供事务快照。
- 增量记录和报告采用可恢复的独立写入策略；同一输出目录使用互斥运行机制。
- 缓存或锁异常应明确报告，不以损坏记录作为跳过依据。异常遗留锁必须在确认无任务后处理，不能无条件强制解锁。
- 逐文件结果至少表达：来源、输出位置、状态、已知的前后大小、处理数量、跳过外链数量、未处理内容和错误原因。
- 文件状态区分成功、无需清理、未变化、部分清理和失败；任务级状态还需区分运行中、请求停止、已停止、已完成及无法继续的任务错误。
- 单文件失败不阻断其他文件；任务基础设施失效须报告任务异常，不能显示全量完成。

### GUI 与可观察性

- 提供输入、输出路径填写和浏览按钮，默认勾选包含子文件夹，并允许关闭。
- 提供开始及停止操作，防止重复启动冲突任务。
- 显示阶段、当前文件、整体进度及按状态分类的数量；无法可靠计算阶段内百分比时，不伪造精确百分比或剩余时间。
- 提供逐文件结果、实际体积差异、错误及部分清理明细，并支持导出报告。
- 成功不逐文件弹窗；用户无需逐个确认。输入校验和任务级异常可以集中提示。
- 非交互入口复用同一业务流程，使外部定期执行成为可能；内置定时器不属于本次范围。

### 资源限制与后续并行

- 旧内存型原型累计解析字节上限为 2 GiB，嵌套深度上限为 16。真实文件批处理已改用区间复制，安全限制为单个 XMP 128 MiB、累计替换数据 256 MiB，另有深度与文档数量限制，不再以整个文件或嵌入 DATA 的累计字节作为 2 GiB 上限。这些限制不是对任意大文件支持的承诺，也不是进程峰值内存上限。
- 必须测量真实文件的峰值内存和耗时，必要时调整内存策略或采用更合适的改写方式；不能通过盲目提高上限宣称支持超大 PSB。
- 并行阶段保留文件级任务边界，由批处理协调方统一管理结果、缓存和报告。尚未确定并行技术及默认并行数，不在本次提前承诺具体数值。

## Testing Decisions

### 主要测试接缝

- 优先使用现有批处理入口作为最高层自动化接缝：建立隔离输入目录，运行完整批处理，断言输出内容、源文件不变、进度与结果、报告、增量复用和停止行为。
- GUI 调用同一批处理入口。新增 GUI 测试只验证路径选择、参数传递、阶段及结果展示、重复启动约束、停止请求和界面响应，不另建模拟的清理实现。
- 保留已有的清理核心及 XMP 针对性测试，处理难以从 GUI 精确定位的边界；不为每个内部辅助函数增加独立的模拟接缝。
- Photoshop 验收属于独立外部行为验证：验证输出能打开、智能对象能编辑、可保存并重新打开，比较图层和实际渲染，不使正式清理依赖 Photoshop。
- 用户已通过确认工单及授权实施 01，确认该工单以现有批处理入口进行真实文件和回归验证；GUI 测试接缝仍在对应后续工单中具体落实，不将本轮验证视为所有 GUI 测试均已批准或完成。

### 什么是有效测试

- 检查可观察结果，而不是私有属性赋值次数或某个内部函数是否被调用。
- 删除行为必须有明确祖先数据的输入，先证明字段存在，再断言被删除、其他字段保留；没有删除目标的文件不能充当删除路径的通过证据。
- 区分原生真实样本、明确注入测试元数据的副本和合成容器；不得将合成容器通过等同于 Photoshop 原生智能对象兼容性通过。
- 不能仅凭重新解析成功或图层数量相同宣称视觉及编辑语义不变。
- 超时、未完成和无法执行的验收明确记录，不计为通过。

### 必需场景

- PSD、PSB、混合大小写扩展名、中文及空格路径、子目录同名文件、递归开启与关闭、空目录、无效目录和输入输出重叠。
- 主文档祖先数据；RDF 属性和元素表达；命名空间前缀变化及重新绑定；同名但不同命名空间的属性；无祖先数据；其他元数据逐字节保留。
- 非法 XML、DTD、暂不支持的编码、无法满足所用路径字节保真门禁的文件，以及写入后结构不一致。
- 可触发 Photoshop“此文档包含未知数据”警告的真实回归样本，覆盖主文档与嵌入式智能对象：确认默认策略为保留图层而非拼合；检查图层与可编辑性、视觉结果及未知数据保留情况。无法安全处理时，断言无修改结果发布、错误原因明确、下一文件继续，且无人工确认阻塞。
- 嵌入 PSD、嵌入 PSB、真实多层嵌套、多实例共享智能对象、version 8 linked 内容描述符、外链及别名、非 PSD 嵌入内容。
- 源文件不变、原样复制、输出不覆盖、目标文件系统不支持发布、写入失败、校验失败、单文件损坏后继续及任务基础设施错误。
- 连续两轮运行；同大小同时间的源内容修改；源在哈希、历史输出校验或清理期间变化；规则升级；输出删除或篡改；失败及部分清理后重试；增量命中输出位置可追踪。
- 当前文件完成后停止；停止后不启动下一文件；界面保持响应；重复开始及任务互斥。
- Photoshop 打开、编辑嵌入内容、保存并重新打开；图层结构及关联检查；清理前后实际渲染像素比较。
- 用户真实大 PSD/PSB 的处理时长、峰值内存、输出大小及与现有 JSX 结果的差异。记录文件特征、测试环境与限制，不预设未经商定的性能阈值。

## Out of Scope

- 在 Photoshop 保存或另存为时拦截并自动清理。
- 以 COM、Photoshop 自动化 Python 包或 JSX 调用作为正常批处理依赖。
- 完全复刻原 JSX 对任意智能对象格式的处理，不支持内容不得伪装成已完成深度清理。
- 清理 AI、PDF、PNG 等非 PSD/PSB 嵌入内容的内部元数据。
- 跟随链接式智能对象并修改输入扫描范围之外的外链源文件。
- 删除全部 XMP、版权或其他非祖先元数据，图层合并、栅格化、降质、重新压缩画面或通用隐私清除。
- 默认覆盖源文件或历史输出；为每轮增量任务重新复制一套完整历史快照。
- 内置定时任务、系统托盘常驻、目录实时监听、云端处理及遥测上传。
- 在当前文件写入过程中强制取消，或强制结束 Photoshop/其他用户进程。
- 串行功能验收之前引入并行清理；预先指定一个未经内存和吞吐测试的并行数。
- 对任意 PSD/PSB 的绝对无损、无限文件大小或跨平台一致性承诺。
- 未经确认的安装包、自动更新和发行方式。
