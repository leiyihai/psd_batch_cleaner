**Status:** ready-for-agent

**Completion:** completed

- [x] 展示成功、无需清理、未变化、部分清理和失败五种文件状态及数量，状态含义与领域术语一致，不把删除数量等同于完整成功。
- [x] 每项可查看来源、实际输出位置、已知的前后大小、字节及易读单位的实际差异、清理文档数量、跳过外链数量、未处理内容和错误原因。
- [x] 部分清理逐项说明未处理内容；失败与无可用输出明确标注，未知大小不伪造为零或误算收益。

## Comments

可基于已有批处理结果模型和稳定的结果场景独立实施，但需通过共享入口完成端到端验证，不能只做静态示例页面。导出格式尚未确认，选型不应改变已确认的数据及安全语义。

### 实施与验收完成

用户确认共享批处理、共享统计/导出、真实 GUI 三个接缝及 UTF-8 JSON/拒绝覆盖选型后按 TDD 实施。新增共享 `prototype/results.py` 统一详情、统计和导出；批处理记录补 `published` 与已知大小，自动报告仍是原逐文件列表格式。GUI 可查看完整路径、精确字节/易读单位差异、已检查文档数、跳过外链、逐项未处理内容及完整错误；缺失值显示未知，不补零；终态显示全部五种状态数量。

仅本轮发布、非失败且大小可核实的成功/无需清理/部分清理计收益；部分清理单列并说明非完整成功，负值保留；历史复用、失败（含已发布后续失败）、未发布和未知大小排除。GUI 与 JSON 使用同一原始记录和同一计算函数。固定 7 行记录覆盖增加/减少/不变/未知大小及全状态，独立期望净减少 984 字节、其中部分清理 -40 字节；真实共享入口及 GUI 另外验收实际文件，不冒充原生 PSD 兼容性验收。

JSON 导出保留中文/完整原始行、任务状态/处理数/总量/错误/原报告路径及统计口径；不是表格，不执行公式文本。独占创建、不覆盖已有用户文件，普通写入故障清理自建未完成文件。后台导出冻结任务/结果快照，阻止新任务和中途关闭但窗口保持响应；取消、I/O/线程/对话框错误反馈后可重试，不改变原批处理状态。报告更新失败时导出真实已接收行并保留明确任务错误，不把较旧可靠报告当作全量清单。
