# 04: GUI 递归扫描与子目录结果映射

**What to build:** 用户在 GUI 中通过默认勾选的“包含子文件夹”控制批处理范围，处理整个目录树并在输出位置按原目录结构找到每个瘦身副本；关闭该选项时只处理输入目录当前层级。

**Blocked by:** 03 — 最小可用中文 GUI：选择目录并完成串行瘦身。

**Status:** ready-for-agent

**Completion:** completed

- [x] GUI 提供默认开启、可关闭的包含子文件夹选项；GUI 与非交互入口共用同一递归参数和扫描行为。
- [x] 识别 PSD/PSB 及大小写不同的扩展名，正确处理中文、空格和多级目录，不处理其他扩展名文件。
- [x] 输出保留输入相对路径，不同子目录中的同名文件互不覆盖；历史输出仍遵循独立运行目录策略。
- [x] 输入和输出目录相互包含时拒绝开始；扫描不跟随符号链接进入其他目录，不把输出重新作为输入。
- [x] 扫描结束后显示可靠的文件总量及整体文件进度；最终结果数量与本轮选择范围一致，空目录有明确反馈。
- [x] 无权限或扫描错误明确反馈，不静默显示为已完成全部扫描；不破坏原稿或已完成输出。
- [x] 用包含嵌套目录、同名文件、混合扩展名、中文路径及空目录的隔离场景，端到端验收递归开启和关闭两种行为，并确认 GUI 选项实际控制任务范围。

## Comments

仅新增扫描范围与路径映射，不引入实时监听或内置计划任务。已运行任务的递归参数固定，不能由界面后续改动影响当前任务。

### 实施与验收完成

按用户确认的共享批处理、真实 GUI、隔离端到端三个接缝实施 TDD。GUI 默认勾选“包含子文件夹”，启动时捕获范围参数并禁用选项；CLI 新增 `--no-recursive`，继续共用同一扫描器。完整扫描后才发布可靠总量，GUI 显示文件计数与确定进度；保留相对路径、历史输出和原有缓存引用策略。真实 junction 测试复现了历史输出被重新作为输入的问题，已补目录联接排除。

可见窗口两轮隔离冒烟分别处理 3 / 3、1 / 1 个文件，全部输入字节不变，输出路径、同名隔离及历史报告保留通过。修正扫描器后最终复跑证据 `.prototype-data/ticket04/20261114_133422_928995/`。权限/设备故障在文件系统边界注入，明确任务异常，不发布部分扫描总量，保留原稿和历史输出。

全套 64 项：59 通过、5 跳过（4 个既有 opt-in；1 个真实符号链接创建因 WinError 1314 缺少权限跳过，未冒充实跑）；10 项 Tk 和 Windows 真实 junction 测试通过。5 个入口/相关模块 mypy 通过；全目录 mypy 另发现 2 个未修改文件的 6 个既有错误，明确留作范围外事项。详见 [04 最终验收记录](../../../docs/ticket04-closeout.md)。不自动推进 05–08，不推送远端。

首轮 Standards 无硬性违规，1 项低优先级局部故障注入重复建议，选择保留以保持测试独立可读。Spec 发现 `os.walk` 会吞目录项类型检查错误；已先补失败测试，再改为 `os.scandir` + 显式不跟随链接的 `stat`，分类异常向上传播，不再误报完整扫描。修正后全套测试、相关类型检查及两轮可见 GUI 冒烟再次通过。
