# 05: 安全停止、单文件失败后继续与任务异常反馈

**What to build:** 用户可以在 GUI 中请求安全停止，当前文件完成或安全失败后不再启动下一项；坏文件不阻断其他文件，任务级故障、锁冲突和停止结果均清楚可见，并能安全开始后续任务。

**Blocked by:** 03 — 最小可用中文 GUI：选择目录并完成串行瘦身。

**Status:** ready-for-agent

**Completion:** completed

- [x] 提供停止操作和请求停止反馈，区分运行中、请求停止、已停止、已完成及任务异常；停止不显示成全部完成。
- [x] 当前文件开始后不在解析或写入中间强行终止，完成或安全失败后停止启动下一文件；清理完成前界面不误报已停止。
- [x] 单个损坏、解析失败或校验失败的文件记录原因且不发布半成品；未请求停止时继续处理后续文件。
- [x] 报告或缓存无法可靠写入、输出基础设施失败等任务级异常明确终止并保留已有记录，不显示全量成功。
- [x] 同一输出目录的任务互斥生效；锁冲突可读且不会覆盖其他任务的锁。异常遗留锁只提供确认无任务后处理的说明，不无条件强制解锁。
- [x] 正常完成、停止及失败后正确释放任务资源并恢复 GUI 操作状态；不强制结束 Photoshop 或其他用户进程。
- [x] 完成至少两文件的停止验收、坏文件后继续、写入及校验失败、任务锁冲突和异常后再次启动的回归；断言输出和报告，不只断言按钮文字。

### 实施与验收完成

用户确认共享批处理、真实 GUI 和隔离文件端到端三个接缝后按 TDD 实施。GUI“安全停止”传本轮独立信号到共享 `run()`；请求后保持忙态且不被阶段通知覆盖，当前文件完成或安全失败、报告与锁处理结束后才收到 `stopped` 并显示已停止。扫描中等待扫描返回，不启动文件处理。正常结束、停止、异常后可重新启动，不强杀线程或进程。

输出阶段系统 I/O 故障、缓存或报告写入失败明确终止；报告失败仍展示本次实际输出，保留最近原子保存的记录并说明报告可能不完整。坏文件/校验拒绝继续后续文件，不发布半成品。锁冲突给出实际路径与确认无任务后处理的中文说明，不动其他任务锁；独占创建后初次写锁失败也清理自有锁。

两文件真实 GUI 写入/校验门闩验收通过：请求时仍忙，结束后只发布第一文件、报告 1 / 2，下一轮安全处理余项；实际第二任务被锁拒绝且锁内容不变。另验证主动损坏暂存文件触发真实校验失败、磁盘写入/发布失败、报告更新失败及故障解除后再次启动。可见窗口证据 `.prototype-data/ticket05/20261114_135036_286960/` 含请求中、已停止、重启、坏文件继续、报告故障和锁冲突截图与文件证据；有效原稿字节与历史输出哈希不变。
