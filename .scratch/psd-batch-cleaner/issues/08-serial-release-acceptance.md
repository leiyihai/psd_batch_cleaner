# 08: 串行桌面版本整体验收与定期运行入口

**What to build:** 用户获得经过同一套代表性文件验证的完整串行桌面工作流，并可通过非交互入口调用相同的深度清理和增量规则，供外部计划任务定期执行；运行方式、错误结果及支持边界有清楚说明。

**Blocked by:** 04 — GUI 递归扫描与子目录结果映射；05 — 安全停止、单文件失败后继续与任务异常反馈；06 — GUI 增量清理：可靠跳过未变化文件；07 — 逐文件结果、真实瘦身统计与报告导出。

**Status:** ready-for-agent

- [ ] 用同一套代表性样本完成目录选择、递归扫描、深度清理、结果展示及导出的 GUI 全流程验收，不以单模块测试代替整体验收。
- [ ] 覆盖首次运行、重复运行、输入更新、规则变化、输出损坏、部分清理重试、单文件失败、任务异常和文件边界停止，验证原稿不变及输出不覆盖。
- [ ] 非交互入口无需 Photoshop 或逐文件人工确认，复用与 GUI 相同的清理、增量、安全和报告逻辑，提供稳定的完成及失败反馈，足以供外部计划任务判断结果。
- [ ] 明确非交互执行中失败、部分清理、任务异常的状态或退出码约定，并验证其不会被错误识别成全部成功；不交付内置定时器。
- [ ] 复验问题文件不阻塞批次，未知数据兼容性遵循保留图层而非拼合；对正常和受限文件都记录实际结果，超时不计为通过。
- [ ] 在隔离副本上完成 Photoshop 打开、编辑嵌入内容、保存后重新打开及渲染比较；验收工具不保存或关闭用户已有文档。
- [ ] 记录真实大文件耗时、峰值内存、结果大小、支持范围及尚存限制；不宣称无限大小、任意格式无损或与 JSX 瘦身量完全一致。
- [ ] 提供安装与运行步骤、GUI 及非交互使用方式、输出和增量复用规则、失败复查与遗留锁处理说明；不把未确认的安装包及自动更新纳入交付。
- [ ] 已有自动测试、GUI 验收及真实文件验收均形成明确记录，未完成或阻塞项保持可见；完成前不将串行版本标记为通过验收。
- [ ] 仅在串行功能通过验收后提出受峰值内存和磁盘吞吐约束的后续并行评估，不在本工单实现并行或提前指定并行数。

同一套 8 份隔离输入包含四份授权真实大文件、真实未知 PSB 提取件和明确标注的正常/更新/损坏对照。可见 GUI 八轮真实执行，完整轮约 162–169 秒，文件边界停止为 2 / 8；与独立 CLI 有效输出哈希一致。CLI 首轮及最终重复轮如实返回 1，纯部分子范围 3、未知原样子范围 0、锁冲突 2；任务异常保留实际已处理数/总量和最近可靠报告，不冒充全部成功。

首次把两个长 CLI 放入 600 秒外围命令，第二轮被外围终止，保留六文件报告与未完成证据，不计通过。已确认该自建 CLI PID 不存在且无任务使用输出后，人工备份仅此验收遗留锁，再以充足时限重做重复轮通过；没有生产强制解锁路径或 Photoshop 强杀/自动重试。该未完成尝试持续公开于 `cli-outer-timeout.json`。
