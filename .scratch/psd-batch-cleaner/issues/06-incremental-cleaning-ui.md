# 06: GUI 增量清理：可靠跳过未变化文件

**What to build:** 用户对同一输入和输出位置重复运行时，通过内容哈希复用有效历史副本，GUI 明确展示检查变化和未变化结果，并能定位被复用的实际输出；发生有效变化时重新清理，不覆盖历史副本。

**Blocked by:** 03 — 最小可用中文 GUI：选择目录并完成串行瘦身。

**Status:** ready-for-agent

**Completion:** completed

- [x] 复用并完善现有增量记录，绑定源身份、源 SHA-256、清理规则版本、处理状态、输出位置及输出 SHA-256；不使用大小和时间作为内容相同的最终依据。
- [x] 连续两轮运行中，完整成功或无需清理且输入、规则和输出均未变化的文件显示未变化，不重复解析、清理或保存，不向本轮目录重复复制历史副本。
- [x] GUI 显示检查变化阶段，未变化结果可定位到历史输出，用户不会误认为本轮目录是一套全新完整副本。
- [x] 输入内容变更，包括同大小同时间的修改、规则升级、输出丢失或篡改，均使旧结果失效并生成新副本。
- [x] 失败和部分清理不作为完整缓存命中，下次仍可重试；不能为减少任务量而静默忽略未完成内容。
- [x] 哈希、历史输出校验或清理期间输入发生变化时，明确失败或重试原因，不复用过期结果、不发布不对应输入的修改副本。
- [x] 损坏缓存及越界输出引用不导致错误跳过或读取指定输出范围外的历史副本；问题有明确反馈，不把任务当作正常全量完成。
- [x] 从 GUI 参数进入共享批处理流程，端到端覆盖首次与二次运行、各类失效和并发修改场景；保留已有哈希回归，不为 GUI 另建缓存实现。

## Comments

内容哈希意味着大文件仍需完整读盘，界面必须说明检查阶段，不承诺零耗时跳过。可在当前层级多文件场景验收，不依赖 04、05、07。

### 实施与验收完成

用户确认共享批处理与真实 GUI → 实际文件结果两个接缝后按 TDD 实施。沿用既有内容哈希、规则与输出校验，不新增 GUI 缓存实现；补缓存结构/字段/源身份/可复用状态校验，以及加载和使用前的输出路径边界检查。损坏记录、绝对/盘符相对/父级跳转和解析后越界引用明确任务异常，保留缓存、历史副本及报告，不读取越界数据、不静默重新清理当作正常完成。

GUI 初始和启动日志说明完整读盘成本；结束显示历史复用数量与“不在本轮重复复制”，输出列及详情可查看实际历史路径。真实 GUI 完成成功/无需清理两轮复用、同大小同时间修改、规则升级、输出丢失/篡改、失败/部分清理重试及修复、哈希/历史校验/清理期间同大小同时间并发输入变化，以及异常缓存恢复；不发布过期副本。真实 Windows junction 测试覆盖加载已越界及加载后切换越界，两者都拒绝读取外部副本。

可见窗口证据 `.prototype-data/ticket06/20261114_160146_695550/` 含首次、复用、失效、并发输入、异常与恢复七轮报告及截图。有效首次输出 SHA-256 不变，无用户素材或 Photoshop 操作。全套回归曾发现旧测试窗口循环引用在 worker GC 中被析构；用两窗口强制 GC 脚本及线程栈复现后，仅调整测试夹具主线程回收，未改变生产 GC、未放宽超时，并补后台 GC 回归。
