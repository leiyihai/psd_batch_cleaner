# 06: GUI 增量清理：可靠跳过未变化文件

**What to build:** 用户对同一输入和输出位置重复运行时，通过内容哈希复用有效历史副本，GUI 明确展示检查变化和未变化结果，并能定位被复用的实际输出；发生有效变化时重新清理，不覆盖历史副本。

**Blocked by:** 03 — 最小可用中文 GUI：选择目录并完成串行瘦身。

**Status:** ready-for-agent

- [ ] 复用并完善现有增量记录，绑定源身份、源 SHA-256、清理规则版本、处理状态、输出位置及输出 SHA-256；不使用大小和时间作为内容相同的最终依据。
- [ ] 连续两轮运行中，完整成功或无需清理且输入、规则和输出均未变化的文件显示未变化，不重复解析、清理或保存，不向本轮目录重复复制历史副本。
- [ ] GUI 显示检查变化阶段，未变化结果可定位到历史输出，用户不会误认为本轮目录是一套全新完整副本。
- [ ] 输入内容变更，包括同大小同时间的修改、规则升级、输出丢失或篡改，均使旧结果失效并生成新副本。
- [ ] 失败和部分清理不作为完整缓存命中，下次仍可重试；不能为减少任务量而静默忽略未完成内容。
- [ ] 哈希、历史输出校验或清理期间输入发生变化时，明确失败或重试原因，不复用过期结果、不发布不对应输入的修改副本。
- [ ] 损坏缓存及越界输出引用不导致错误跳过或读取指定输出范围外的历史副本；问题有明确反馈，不把任务当作正常全量完成。
- [ ] 从 GUI 参数进入共享批处理流程，端到端覆盖首次与二次运行、各类失效和并发修改场景；保留已有哈希回归，不为 GUI 另建缓存实现。

## Comments

内容哈希意味着大文件仍需完整读盘，界面必须说明检查阶段，不承诺零耗时跳过。可在当前层级多文件场景验收，不依赖 04、05、07。
