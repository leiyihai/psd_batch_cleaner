# 03: 最小可用中文 GUI：选择目录并完成串行瘦身

**What to build:** 用户可以启动独立的简洁中文窗口，填写或浏览输入、输出目录，点击开始，对输入目录当前层级的 PSD/PSB 完成串行瘦身，并查看当前阶段、文件和基本结果。复用已验收的批处理能力，耗时任务不占用 GUI 事件循环。

**Blocked by:** 01 — 真实 PSD/PSB 深度清理与大文件验收；02 — 未知数据文档不中断批处理，禁止自动拼合。

**Status:** ready-for-agent

- [ ] 提供输入目录、输出目录输入框及浏览按钮、开始按钮、当前阶段、当前文件及基本结果展示；中文界面布局清晰，长路径与错误信息可读。
- [ ] 本工单先交付当前目录批处理，不递归子目录；为后续递归选项保留同一批处理调用方式，不另写扫描或清理实现。
- [ ] 开始前校验目录存在性、可写性及输入输出隔离；不能相互包含，原稿和历史输出不覆盖，无需清理的文件原样复制。
- [ ] 正常清理不启动 Photoshop；保留既有深度清理、外链保护、部分清理及安全拒绝行为。
- [ ] 在 GUI 之外执行扫描、哈希、清理、写入和校验；将现有通知整理成 GUI 与非交互入口可共同消费的阶段和结果事件，不新增一套 GUI 专用业务逻辑。
- [ ] 用户可以看见检查变化、清理、校验及文件完成反馈；没有可靠阶段内进度时显示阶段状态，不伪造百分比或剩余时间。
- [ ] 处理时窗口仍能响应重绘和交互；运行中不能重复启动同一窗口任务或修改当前任务的有效参数，结束后恢复可操作状态。
- [ ] 成功不逐文件弹窗；单文件错误在基本结果中可见，任务启动或基础设施错误有明确反馈，不误报全量完成。
- [ ] 完成目录输入到输出结果的 GUI 冒烟验收，并通过现有批处理回归；自动测试检查参数、事件和外部结果，不依赖清理私有实现的调用次数。

## Comments

依赖 01、02 是用户确认的交付顺序，不表示技术上无法提前绘制界面。GUI 框架尚未确定，实施时选定并记录必要理由。停止交互、递归扫描、增量结果展示和完整报告分别由后续工单交付。
